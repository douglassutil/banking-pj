# Stack Strategy — Training Platform

This document defines the official strategy for selecting, maintaining, and evolving technology stacks used in the training platform.

The goal is to ensure that stack decisions are intentional, consistent, and aligned with learning objectives.

---

# Purpose

Stacks in this project are not chosen only for popularity.

They are chosen to maximize learning value, employability, and architectural clarity.

Every stack must serve a specific learning level and training purpose.

---

# Core Principle

A stack exists to teach a capability.

Not to follow trends.

---

# Stack Selection Criteria

A new stack should be introduced only when it satisfies at least one of the following conditions.

---

## Learning Relevance

The stack teaches a capability not covered by existing stacks.

Examples:

Backend specialization

Mobile development

Event-driven systems

---

## Market Relevance

The stack is widely used in real-world systems.

Examples:

React

Angular

.NET

Node.js

---

## Pedagogical Value

The stack provides a clear learning progression.

Examples:

Simple mental model

Strong documentation

Predictable architecture

---

# When to Create a New Stack

Create a new stack when:

A new learning track is introduced

A new platform is targeted

A new capability must be taught

---

# Examples

Valid reasons:

Mobile development track

Create:

starter-flutter-beginner

---

Backend specialization track

Create:

starter-dotnet-backend

---

Invalid reasons:

New framework is trending

Personal curiosity

Minor technical preference

---

# Stack Lifecycle

Every stack follows a lifecycle.

---

## Introduction

Stack is added to the platform.

Used in experimental or pilot training.

---

## Adoption

Stack becomes part of official training.

Used in structured learning paths.

---

## Maintenance

Stack is actively supported.

Receives updates and improvements.

---

## Deprecation

Stack is phased out.

Replaced by a newer alternative.

---

# Deprecation Rules

A stack may be deprecated when:

The technology becomes obsolete

Maintenance cost becomes too high

Industry demand significantly declines

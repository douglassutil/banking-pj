# Sprint 10 — Code Quality

This sprint introduces code quality practices and refactoring techniques.

The student will review existing code, improve readability, and organize files to follow consistent standards.

This is the moment where the system evolves from working code into maintainable code.

---

# Objective

Improve the quality, readability, and organization of the existing codebase without changing functionality.

---

# Concepts Introduced

Refactoring

Code readability

Naming conventions

Code organization

Technical debt

Maintainability

---

# Why This Matters

Professional software is not only about making features work.

It is about keeping the system understandable and maintainable over time.

Poor code quality increases bugs, slows development, and makes collaboration difficult.

Learning to improve code safely is a critical professional skill.

# Tasks

Open the backend project

Review controller, service, and repository files

Identify duplicated code

Rename variables and methods to use clear and consistent names

Organize files into proper folders if needed

Remove unused code

Ensure consistent formatting

Run the application to verify behavior remains unchanged

---

# Expected Result

The codebase becomes easier to read and understand.

No functionality changes.

The system continues running correctly.

---

# Verification Steps

Run the application

Execute core features:

Create account

List accounts

Create transaction

Verify behavior remains the same

Review code readability with a peer or mentor

---

# Common Mistakes

Changing functionality during refactoring

Renaming variables inconsistently

Removing necessary code

Skipping tests after refactoring

---

# Troubleshooting

If the system stops working:

Review recent changes

Check logs for errors

Revert the last modification

Restart the application

---

# Code Quality Checklist

[ ] Variable and function names are clear

[ ] No duplicated code remains

[ ] Files are organized correctly

[ ] Application behavior remains unchanged

---

# Definition of Done

The sprint is complete when:

The code is cleaner and easier to read

No functionality is broken

The student understands the purpose of refactoring

---

# Optional Challenge

Extract repeated logic into reusable functions.

Apply consistent naming across the entire module.

---

# Reflection Questions

Why is readable code important for teams?

What risks exist when refactoring code?

How can small improvements reduce long-term maintenance cost?

---

# Mentor Notes

Encourage small, incremental refactoring steps.

Emphasize verifying behavior after each change.

Discuss the concept of technical debt and how refactoring reduces it.

# Sprint 11 — Code Organization & Cleanup

## Objective

Improve code organization, readability, and consistency without changing functionality.

---

## What You Will Learn

- How to refactor safely
- Naming conventions
- Folder organization
- Code readability practices

---

## Prerequisites

- Sprint 0 to Sprint 10 completed

---

## Step-by-Step Tasks

### 1) Review folder structure

Ensure files are organized by feature.

Example:

```text
health/
  dto/
  health.controller.ts
  health.service.ts
  health.module.ts
```

---

### 2) Improve naming

Rename variables, methods, and files to be clear and consistent.

---

### 3) Remove unused code

Delete unused imports, variables, and files.

---

### 4) Standardize formatting

Apply consistent formatting across files.

---

### 5) Simplify logic

Refactor complex or duplicated logic into reusable functions.

---

### 6) Verify behavior

Run the system and test all features:

- Create data
- Read data
- Frontend display

---

## Expected Result

- Code is cleaner and easier to understand
- No functionality changes

---

## Verification Checklist

- [ ] Naming is consistent
- [ ] No unused code
- [ ] Structure is clear
- [ ] Application still works

---

## Definition of Done

- Code is easier to read
- Structure is consistent
- No regressions introduced

---

## Common Mistakes

- Changing functionality during refactor
- Renaming inconsistently
- Removing necessary code

---

## Reflection Questions

- Why is clean code important?
- How does organization help teams?
- What risks exist when refactoring?

---

## Mentor Notes

Encourage small changes and frequent testing.

This is the final polish before deployment.

# Mentor Guide — Beginner Developer Training Program

This guide defines how mentors should support, guide, and evaluate students during the training program.

It ensures consistency in teaching, feedback, and expectations across different mentors.

---

# Your Role as a Mentor

You are not expected to write code for the student.

You are expected to:

- Guide decision making
- Encourage problem solving
- Provide feedback
- Maintain learning pace
- Ensure professional habits

Your mission is to help the student become independent.

Not dependent.

---

# Core Principle

Do not solve problems for the student.

Instead:

Help them think.

---

# What a Mentor Should Do Daily

Daily responsibilities:

1 — Review student progress

2 — Answer questions when needed

3 — Validate completed tasks

4 — Encourage consistent work

5 — Identify learning gaps early

---

# What a Mentor Should NOT Do

Avoid these behaviors.

Writing code for the student

Fixing problems without explanation

Allowing tasks to be skipped

Ignoring recurring mistakes

Rushing the learning process

---

# Weekly Mentor Routine

At the end of each week:

- Review completed sprints
- Validate functionality
- Discuss challenges faced
- Suggest improvements
- Confirm readiness for next sprint

---

# How to Review Student Work

Use this process.

Step 1 — Run the application

Step 2 — Test implemented features

Step 3 — Review code structure

Step 4 — Provide feedback

---

# What to Look For in Code

Correct behavior

Readable code

Consistent naming

Proper structure

Error handling

Testing discipline

---

# How to Give Feedback

Feedback should be:

Clear

Specific

Actionable

Respectful

---

# Example Feedback (Good)

The feature works correctly.

Consider extracting this logic into a reusable function.

---

# Example Feedback (Bad)

This code is wrong

---

# Signs the Student Is Progressing Well

The student:

- Completes tasks consistently
- Tests their work
- Fixes errors independently
- Writes readable code
- Asks thoughtful questions

---

# Warning Signs to Watch For

The student:

- Skips tasks
- Copies code blindly
- Avoids debugging
- Repeats the same mistakes
- Stops asking questions

---

# When to Intervene

Intervene when:

The student is blocked for more than one day

The student repeatedly makes the same mistake

The student misunderstands a core concept

The system stops working entirely

---

# How to Intervene

Do not provide the answer immediately.

Instead:

Ask guiding questions.

Example:

What happens when you run the application?

What error message do you see?

What part of the code controls this behavior?

---

# Expected Pace

Normal pace:

1 sprint per week

If the student struggles:

Slow down

Do not skip content

---

# Evaluation Criteria

Evaluate the student based on:

Consistency

Problem-solving ability

Code quality

Understanding of concepts

Professional behavior

---

# Graduation Criteria

The student is ready to complete the program when:

All sprints are completed

Application runs correctly

Application is deployed

CI/CD pipeline works

Student explains how the system works

---

# Final Mentor Goal

Your goal is not to produce code.

Your goal is to produce developers.

# Evaluation Checklist — Beginner Developer Training Program

This document defines the official criteria used to evaluate student progress and determine readiness for completion of the training program.

It ensures evaluation is objective, consistent, and based on observable behavior.

---

# How This Checklist Is Used

This checklist should be used:

- At the end of each sprint
- During weekly reviews
- At program completion

Evaluation should be based on evidence.

Not opinion.

---

# Evaluation Levels

Each item should be evaluated using one of the following levels:

NOT MET

PARTIALLY MET

FULLY MET

---

# Section 1 — Work Discipline

The student demonstrates consistent professional behavior.

- Attends scheduled sessions
- Works regularly
- Follows the daily routine
- Completes tasks in order
- Avoids skipping steps
- Maintains focus during work sessions

---

# Section 2 — Code Quality

The student writes maintainable and readable code.

- Code is readable
- Variable names are meaningful
- Functions are small and focused
- Code structure follows project patterns
- No unnecessary duplication
- Errors are handled properly

---

# Section 3 — Problem Solving

The student demonstrates the ability to debug and resolve issues.

- Reads error messages carefully
- Attempts solutions before asking for help
- Identifies root causes
- Fixes problems independently
- Explains the solution after fixing the issue

---

# Section 4 — Testing Discipline

The student verifies functionality before marking tasks as complete.

- Runs the application after changes
- Performs manual tests
- Fixes detected issues
- Confirms expected behavior
- Avoids submitting untested code

---

# Section 5 — Version Control

The student uses Git correctly.

- Commits frequently
- Writes clear commit messages
- Pushes code regularly
- Avoids large unstructured commits
- Maintains a clean commit history

---

# Section 6 — System Understanding

The student understands how the system works.

The student can explain:

- What the application does
- How the frontend communicates with the backend
- What an API endpoint is
- How authentication works
- How data is stored
- How the application is deployed

---

# Section 7 — Feature Implementation

The student successfully implements system features.

- Features behave correctly
- UI responds as expected
- Data is saved properly
- Validation works
- Error handling works

---

# Section 8 — Deployment Readiness

The student can run and deploy the system.

- Runs the application locally
- Builds the project successfully
- Runs the system using Docker
- Deploys the application to Fly.io
- Verifies production environment

---

# Section 9 — CI/CD Understanding

The student understands automated workflows.

- Explains what CI means
- Explains what CD means
- Understands workflow execution
- Reads workflow logs
- Identifies failed builds

---

# Final Graduation Criteria

The student is ready to complete the program when ALL of the following are true:

- All sprints completed
- Application runs locally
- Application deployed successfully
- CI/CD pipeline working
- Core concepts explained clearly
- Code passes review checklist

---

# Optional Scoring Model

Mentors may optionally assign scores.

NOT MET = 0

PARTIALLY MET = 1

FULLY MET = 2

Suggested interpretation:

0–9   Needs improvement

10–17 Developing

18–24 Ready

---

# Final Decision

The final decision should be based on:

Consistency

Understanding

Reliability

Professional behavior

Not speed.

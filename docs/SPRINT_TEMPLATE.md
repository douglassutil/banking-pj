# Sprint Template — Training Platform

This document defines the standard structure that every sprint must follow.

The goal is to guarantee consistency, predictability, and clarity across all training tracks and stacks.

Every sprint must use this template.

---

# Sprint Structure Philosophy

A sprint is not just a task list.

A sprint is a learning unit.

Each sprint must:

- Teach one main concept
- Produce a visible result
- Reinforce previous knowledge
- Be achievable without frustration

---

# Standard Sprint Template

Use this structure when creating any sprint.

---

# Sprint X — Title

Example:

Sprint 3 — Account Entity

---

# Objective

Describe the main goal of the sprint.

Example:

Create the Account entity and understand database relationships.

---

# Concepts Introduced

List the main technical concepts taught in this sprint.

Examples:

Entity modeling

Database relationships

Foreign keys

---

# Why This Matters

Explain the real-world relevance of the concept.

Example:

Most business systems depend on relationships between data.

Understanding this concept is essential for building reliable applications.

---

# Prerequisites

List what the student must already know before starting this sprint.

Example:

Previous sprint completed

Basic understanding of database tables

---

# Tasks

Provide a clear, step-by-step list of actions.

Example:

Create Account entity

Define relationship to User

Generate migration

Run migration

---

# Expected Result

Describe what the system should do after completing the sprint.

Example:

Account table exists in database.

Relationship to User works correctly.

---

# Verification Steps

Explain how the student confirms success.

Example:

Run database client

Check table structure

Create test record

---

# Common Mistakes

List typical errors beginners make.

Examples:

Missing migration execution

Incorrect foreign key definition

Database connection failure

---

# Troubleshooting

Provide solutions for common issues.

Examples:

Restart Docker

Reset database

Check environment variables

---

# Code Quality Checklist

Before finishing the sprint, verify:

[ ] Code compiles

[ ] No runtime errors

[ ] Naming is clear

[ ] Files are organized correctly

---

# Definition of Done

The sprint is complete when:

The feature works as expected

The system runs without errors

The student understands the concept

---

# Optional Challenge

Provide an extra task for advanced learners.

Example:

Add an additional validation rule.

---

# Reflection Questions

Ask questions to reinforce learning.

Examples:

What happens if the relationship is removed?

Why is this validation necessary?

---

# Mentor Notes (Optional)

Provide guidance for mentors.

Examples:

Observe whether the student understands the data model.

Encourage debugging instead of giving direct answers.

---

# Reuse Rule

All new sprints must be created using this template.

Never create ad-hoc sprint structures.
